    CKS Real World exam — 13 practice tasks

    Luyện trên cluster lab của bạn. Đọc đề → làm với kubernetes.io/docs → rồi mới xem pass criteria.

    Format: 13 tasks · ~CKS pace Rule: your lab only Docs: kubernetes.io/docs
    Outline 13 chủ đề lấy từ file PDF ôn (CIS kubelet/etcd, API server, ImagePolicyWebhook, Dockerfile, runtime, SA, SBOM, Docker daemon, TLS, audit, NetPol, Ingress TLS). Đây là đề luyện viết lại — không phải đề thi CNCF chính thức, không copy đáp án dump.

    Clock strategy

    • ~16 task / 120 phút → 7–8 phút/task; vài task ăn 15–20 phút.
    • 60 giây: quick win hay time sink? Bookmark sink, lấy điểm dễ trước.
    • Static pod / restart API server: làm gần cuối, verify cluster còn sống.
    • Chỉ sửa đúng chỗ đề yêu cầu (Dockerfile: một instruction; manifest: một field).

    Task 1 — CIS: kubelet + etcd

    Domain: Cluster setup / CIS. Docs: kubelet config, etcd.

    Question. Scanner CIS (kube-bench kiểu) FAIL trên cluster kubeadm:

    • kubelet: anonymous auth đang bật; authorization mode không được là AlwaysAllow — dùng webhook nếu được.
    • etcd: client cert auth phải bật.

    Sửa bằng config, restart component cho setting có hiệu lực. Runtime có thể là Docker — dùng docker nếu cần xem container control-plane.

    Pass when: kubelet không nhận anonymous; authz không AlwaysAllow; etcd --client-cert-auth=true (hoặc tương đương trong file config); process đã restart.

    Where: thường /var/lib/kubelet/config.yaml; etcd flags trong static pod /etc/kubernetes/manifests/etcd.yaml.

    Task 2 — API server: anonymous, RBAC, NodeRestriction

    Domain: Cluster hardening. Docs: kube-apiserver, admission controllers.

    Question. Siết kube-apiserver trên node control-plane:

    • Tắt anonymous authentication.
    • Authorization mode phải gồm RBAC (và Node nếu đề yêu cầu), không AlwaysAllow.
    • Bật admission NodeRestriction.

    Pass when: flags trên static pod apiserver đúng; API server Ready sau khi manifest đổi.

    Where: /etc/kubernetes/manifests/kube-apiserver.yaml.

    Task 3 — ImagePolicyWebhook (fail closed)

    Domain: Supply chain / admission. Docs: admission controllers, ImagePolicyWebhook.

    Question. Cluster đã có scanner HTTPS. Config admission còn dở:

    1. Enable plugin ImagePolicyWebhook trên API server + trỏ --admission-control-config-file.
    2. Khi backend scanner lỗi: deny image (fail closed — không default-allow).
    3. Kubeconfig webhook trỏ đúng URL scanner.
    4. Mount hostPath thư mục config vào static pod apiserver nếu file nằm trên host.
    5. Apply manifest test image xấu — phải bị reject. Xem log scanner nếu đề cho path log.

    Pass when: deploy image bị cấm fail; log scanner có request (nếu có log).

    Task 4 — Dockerfile + Deployment (đúng một chỗ)

    Domain: Microservices / supply chain. Docs: Pods, securityContext.

    Question.

    • Dockerfile: sửa một instruction security (thường USER root → user không privileged). Không thêm/xóa dòng. Không docker build.
    • Deployment YAML: sửa một field (privileged / runAsUser / allowPrivilegeEscalation). Không thêm/xóa field.
    • Nếu đề cho UID unprivileged — dùng đúng UID đó (hay gặp 65535 / nobody).

    Pass when: file trên disk đúng một chỗ; image không cần build.

    Task 5 — Tìm workload đọc /dev/mem (hoặc syscall lạ)

    Domain: Runtime / Falco. Docs: Falco, pods.

    Question. Có process/pod đang đụng device nhạy (/dev/mem, privileged, hostPath nguy hiểm). Dùng Falco / crictl / kubectl tìm namespace + pod + container. Ghi tên vào file đề yêu cầu. Có thể phải xóa hoặc siết workload.

    Pass when: đúng pod; evidence (Falco rule hit hoặc mounts).

    Task 6 — Immutable container filesystem

    Domain: Runtime immutability. Docs: securityContext.

    Question. Deployment cho sẵn: bật readOnlyRootFilesystem: true. Nếu app cần ghi, thêm volume (emptyDir) + volumeMount đúng path — không privileged.

    Pass when: pod Running; rootfs read-only; app không CrashLoop vì không ghi được.

    Task 7 — Tắt automount ServiceAccount token

    Domain: Service accounts. Docs: ServiceAccount, pods.

    Question. Namespace X: pod/deployment đang mount token SA mặc định. Tắt automount ở Pod spec và/hoặc SA automountServiceAccountToken: false đúng phạm vi đề (default SA vs named SA). Restart workload.

    Pass when: pod mới không còn volume token; app không cần API thì không mount.

    Task 8 — Package vuln + SBOM

    Domain: Supply chain. Docs: (tool trên node: trivy / syft — theo đề).

    Question. Image hoặc filesystem cho sẵn: tìm package version dễ tổn thương (CVE critical). Xuất SBOM SPDX (hoặc CycloneDX) vào path đề cho. Không bịa CVE — dùng scanner.

    Pass when: file SBOM tồn tại, format đúng; câu trả lời version khớp scan.

    Task 9 — Hardening Docker daemon trên node

    Domain: System hardening. Docs: dockerd, CIS docker.

    Question. Trên worker: siết daemon.json / systemd drop-in theo đề (userland-proxy, live-restore, no-new-privileges, userns, logging). Restart docker. Không phá kubelet.

    Pass when: docker info / file config khớp; node Ready.

    Task 10 — TLS Secret cho Deployment/Ingress

    Domain: Ingress / secrets. Docs: Secrets, Ingress TLS.

    Question. Có cert/key trên disk. Tạo Secret kiểu TLS trong đúng namespace. Gắn vào Ingress hoặc Deployment theo đề (tls.crt / tls.key). Không commit private key vào ConfigMap.

    Pass when: Secret type kubernetes.io/tls; Ingress spec.tls trỏ secretName đúng.

    Task 11 — Audit policy: tạo + mở rộng

    Domain: Logging. Docs: Auditing.

    Question.

    1. Policy audit YAML: log RequestResponse cho secrets (hoặc group đề cho); Metadata cho phần còn lại; không log RequestReceived ồn.
    2. API server: --audit-policy-file, --audit-log-path, volume mount.
    3. Extend: thêm rule cho một resource khác (configmaps / exec).

    Pass when: file log có event sau khi get secret; apiserver healthy.

    Task 12 — NetworkPolicy cô lập namespace

    Domain: Cluster setup. Docs: NetworkPolicy.

    Question. Default deny ingress (và egress nếu đề bảo). Allow: cùng namespace / namespace label / port cụ thể tới một app. DNS (53) nếu egress deny. Không mở 0.0.0.0/0 trừ khi đề bắt.

    Pass when: probe từ namespace lạ fail; probe được allow pass.

    Task 13 — Ingress TLS + redirect HTTP→HTTPS

    Domain: Ingress. Docs: Ingress, certs.

    Question. Ingress (nginx hoặc Cilium tùy lab): TLS secret, host đúng, backend Service. Bật redirect HTTP sang HTTPS (annotation hoặc HTTPRoute tùy controller trên cluster).

    Pass when: :443 TLS ok; :80 redirect; không terminate nhầm.

    Self-check trước khi nộp (lab)

    • Đúng context / namespace.
    • Static pod: đợi Ready, không để apiserver CrashLoop.
    • Đề nói “do not build” / “do not add fields” thì tuân thủ.
    • Ghi answer file đúng path nếu có.

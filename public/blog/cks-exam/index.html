    CKS Exam — Certified Kubernetes Security Specialist

    CKA chứng minh bạn chạy được cluster. CKS chứng minh bạn siết được nó khi có người cố ý phá.

    Tác giả: Hieu Nguyen (Ryan) Kỳ: CNCF / Linux Foundation Cập nhật: Aug 2026

    CKS là kỳ thi thực hành: bảo mật ứng dụng container và nền Kubernetes từ lúc build, lúc deploy, đến lúc runtime. Điều kiện: đã có CKA còn hạn. Chứng chỉ CKS thường có hiệu lực 2 năm — luôn đối chiếu trang CNCF CKS trước khi đăng ký.

    Lệ phí quanh mức vài trăm USD; Black Friday / cuối năm hay có giảm. Curriculum và trọng số domain CNCF cập nhật theo năm — PDF hiện hành trên site CNCF mới là nguồn sự thật.

    What's on the exam?

    Thi hands-on, không trắc nghiệm. Các nhóm kiến thức dưới đây bám curriculum phổ biến (trọng số có thể đổi — check PDF mới nhất):

    Cluster Setup (~10%)

    • NetworkPolicy siết north-south / east-west.
    • Rà Kubernetes components theo CIS benchmark.
    • Ingress có TLS, không phơi dashboard / GUI không cần.
    • Che metadata endpoint (cloud IMDS) khỏi Pod không tin.

    Cluster Hardening (~15%)

    • Khóa Kubernetes API: anonymous, insecure port, bind address.
    • RBAC tối thiểu; không cluster-admin “cho tiện”.
    • ServiceAccount: tắt automount mặc định, token ngắn hạn, quyền đúng việc.

    System Hardening (~15%)

    • Thu hẹp OS trên node (package, user, ssh).
    • IAM / cloud identity cho node nhỏ nhất có thể.
    • Egress ra internet có chủ đích.
    • AppArmor / seccomp trên workload.

    Minimize Microservice Vulnerabilities (~20%)

    • Security context: non-root, drop capabilities, read-only rootfs, no privilege escalation.
    • Secrets: không nhét env nếu không bắt buộc; mã hóa etcd; RBAC đọc secret hẹp.
    • Runtime sandbox (gVisor / Kata) khi multi-tenant.

    Supply Chain Security (~20%)

    • Image nhỏ, distroless / distro tối giản.
    • Chỉ chạy image đã scan, ký, allowlist (admission).
    • Static analysis manifest (PSS, Kyverno/OPA, kube-score kiểu lab).
    • CVE trên image — Trivy / Grype trong pipeline, không chỉ “trên laptop”.

    Monitoring, Logging & Runtime Security (~20%)

    • Audit log API server: ai gọi gì, lúc nào.
    • Container immutability: không exec lung tung, không ghi filesystem nếu policy cấm.
    • Hành vi syscall / file (Falco hoặc tương đương) — detect, không phải “cài xong quên”.
    • Điều tra: logs, events, forensic tối thiểu khi Pod lạ.

    Exam day

    • Online, proctor theo thời gian thực (PSI Bridge).
    • 2 giờ, toàn thực hành. Pause không dừng đồng hồ.
    • Kết quả thường trong ~24 giờ qua email.
    • Fail lần 1 thường còn một retake trong voucher; hết hai lần thì mua lại. Policy cụ thể nằm trên Linux Foundation.
    • Đổi lịch / hủy: cần báo trước (thường 24 giờ) — trễ coi như mất lượt.

    Phòng thi: yên, riêng, sáng; không cửa sổ / đèn mạnh sau lưng; một mình; bàn trống. Webcam phải quay được phòng. Không VM để thi dù syscheck “pass”. Chrome mới, mạng ổn, tắt VPN/torrent/stream. Một màn phụ thường được phép — xem hướng dẫn PSI hiện hành.

    Kiểm tra máy: PSI syscheck và tips CKA/CKAD/CKS.

    Proctor: không nói chuyện với người khác, không đọc đề to, không tai nghe (trừ y tế), không giấy nháp ngoài notepad trên exam UI, không che mặt, nước trong suốt không nhãn. Code of conduct đầy đủ nằm trên trang LF — đọc trước ngày thi.

    Allowed tools & docs

    Trong VM thi bạn được:

    • Terminal, man, file distro dưới /usr/share/*, package có sẵn.
    • Browser chỉ tài liệu được phép — điển hình:
    • https://kubernetes.io/docs/ (kể cả search trên docs)
    • https://kubernetes.io/blog/

    Không bookmark blog cá nhân, không ChatGPT, không repo GitHub ngoài phạm vi đề cho. Domain phụ chỉ khi nằm trong danh sách LF công bố cho kỳ đó.

    kubectl autocomplete nên bật ngay phút đầu (giống CKA). Làm lệnh, đừng copy-paste mù từ tab docs.

    How I study

    1. CKA còn nóng. YAML, context, jsonpath, NetworkPolicy cơ bản phải gõ được không nghĩ.
    2. Một lab một domain. Ví dụ tối: chỉ NetworkPolicy + PSS; tối khác: Trivy + admission.
    3. Đồng hồ 2 giờ. Killer.sh (đi kèm nhiều voucher) hoặc lab tương đương — flag đề, skip, quay lại.
    4. Docs map. Biết URL NetworkPolicy, Pod Security, RBAC, Secrets, Audit — không search từ “kubernetes” mỗi lần.
    5. Không học exploit. CKS hỏi control: policy, flag kube-apiserver, seccomp profile, image digest.

    Checklist gõ thuộc trước giờ thi:

    # context + ns
kubectl config get-contexts
kubectl config use-context ...
kubectl -n <ns> get po,ing,netpol,sa,role,rolebinding

# dry-run khi sửa YAML
kubectl apply --dry-run=client -f . -o yaml

# image / security context
kubectl get po <name> -o jsonpath='{.spec.containers[*].image}'

    Tóm tắt

    • CKS = CKA + security trên build / deploy / runtime.
    • Sáu domain; supply chain và runtime thường nặng điểm.
    • 2 giờ, proctor, docs chỉ kubernetes.io.
    • Luyện tốc độ YAML và đường dẫn docs, không luyện “hacker cluster người khác”.

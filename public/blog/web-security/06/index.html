    Chương 6: Access Control

    OWASP A01: user làm việc không thuộc quyền. DevOps hay mở nhầm admin Service.

    Tác giả: Hieu Nguyen (Ryan) Phần: II — Auth Cập nhật: Aug 2026

    Khái niệm

    Mỗi request phải hỏi: principal này có được object/action này không — trên server, không phải ẩn nút trên UI.

    Phân loại

    • Vertical: user → admin function.
    • Horizontal: user A xem object của B (IDOR).
    • Context: đúng role nhưng sai trạng thái (sửa đơn đã thanh toán).

    IDOR

    Object ID do client chọn (/invoices/318) mà server không kiểm tra sở hữu. UUID không phải control — chỉ làm enumeration chậm hơn. Mass assignment / filter trên query cũng cùng lớp.

    Leo quyền dọc

    Admin path không authz, parameter role=admin tin từ client, method override (X-HTTP-Method-Override) đi nhánh khác policy. Ingress mở /admin ra internet là misconfig vận hành.

    Cách phát hiện

    • Hai tài khoản lab: gọi object của nhau.
    • Bỏ cookie admin, gọi lại path admin.
    • Kiểm tra Service/Ingress không expose dashboard.

    Phòng chống

    1. Deny by default.
    2. Authz trung tâm (policy library), không copy if role rải controller.
    3. RBAC/ABAC server-side; ID nội bộ, không tin ID client nếu có thể.
    4. Test tự động: user A không đọc resource B.

    Góc nhìn DevOps

    NetworkPolicy không thay authz app. Nhưng không expose admin UI; IP allowlist / VPN / mesh mTLS cho service nội bộ. Audit log: ai đọc object nào.

    Tóm tắt

    • UI ẩn không phải authz.
    • IDOR = thiếu check sở hữu.
    • Deny by default.
    • Đừng public admin Ingress.

    Câu hỏi ôn tập

    1. Horizontal khác vertical?
    2. UUID hết IDOR không?
    3. Vì sao tin role trên JSON body sai?
    4. Test tối thiểu cho IDOR trong CI?
    5. NetworkPolicy đủ thay access control app?

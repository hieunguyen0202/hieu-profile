    Chương 19: Open Redirect

    redirect=https://… nghe hiền. Phishing và token trên URL thì không.

    Tác giả: Hieu Nguyen (Ryan) Phần: V — Server-side Cập nhật: Aug 2026

    Khái niệm

    Param redirect đưa user sang host attacker. Dùng trong phishing và đôi khi chuỗi OAuth/token.

    Phòng chống

    • Allowlist path nội bộ (relative) hoặc host cố định.
    • Cấm scheme lạ (javascript:, //evil).
    • OAuth: exact redirect_uri.

    Góc nhìn DevOps

    WAF rule mở; control chính là code/IdP config. Không log full URL có token.

    Tóm tắt

    • Allowlist đích.
    • Relative path an toàn hơn URL đầy đủ.
    • OAuth URI chặt.

    Câu hỏi ôn tập

    1. Open redirect thành phishing thế nào?
    2. //host khác https://host chỗ nào?
    3. Vì sao next=/dashboard ổn hơn next=https://…?
    4. Liên quan OAuth?
    5. Header Location có cần allowlist?

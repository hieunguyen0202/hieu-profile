    Chương 4: Authentication

    Login sai không phải “user ngu”. Đó là control bạn chưa siết.

    Tác giả: Hieu Nguyen (Ryan) Phần: II — Auth Cập nhật: Aug 2026

    Khái niệm

    Authentication trả lời bạn là ai. Authorization trả lời bạn được làm gì. Nhầm hai thứ này thì 401/403, MFA, và RBAC đều đặt sai chỗ.

    Cách hoạt động

    User gửi chứng cứ (password, OTP, WebAuthn, federated token) → server kiểm tra → phát session hoặc JWT. Mọi bước sau login đều giả định bước này đúng.

    Các lớp lỗ hổng thường gặp

    Username / email enumeration

    Message khác nhau (“user không tồn tại” vs “sai mật khẩu”), thời gian response khác nhau, hoặc reset-password tiết lộ account. Attacker chỉ cần danh sách email đã leak.

    Đoán mật khẩu và lockout giả

    Không rate-limit, lockout chỉ theo username (đổi IP/username là né), CAPTCHA chỉ trên UI không trên API. Password spray: một mật khẩu yếu trên nhiều tài khoản — log trông “thưa” hơn brute một user.

    MFA làm cho có

    OTP gửi cùng response login, MFA cookie không bind device, backup code không rotate, “remember this device” sống hàng năm. Bypass thường ở nhánh phụ (reset, OAuth, API cũ) chứ không phải form login chính.

    Password reset

    Token ngắn, một lần, hết hạn; Host header không được dùng để ghép link (Chương 2). Token trong URL thì access log giữ secret.

    Remember me

    Selector + verifier hashed phía server; đừng để token login thuần trong cookie dài hạn.

    Cách phát hiện

    • So response login fail: status, length, thời gian.
    • API /login và /forgot-password có cùng policy rate-limit không.
    • Audit: MFA bắt buộc nhóm admin chưa.

    Phòng chống

    • Thông báo lỗi login chung.
    • Rate-limit + backoff theo IP và account; alert spray.
    • MFA phishing-resistant (WebAuthn) cho privileged.
    • Reset: token random, TTL ngắn, invalidate session cũ.
    • Password: check denylist / leak, không tự roll hash yếu.

    Góc nhìn DevOps

    IdP (Keycloak, Cognito, Entra) tập trung policy. WAF rate-limit là lớp phụ. Secret SMTP/SMS cho OTP nằm Vault, không env Pod. Log auth event (success/fail/MFA/reset) đủ field nhưng không log password.

    Tóm tắt

    • Auth ≠ authz.
    • Enumeration và reset là lỗ hay hơn “bẻ hash”.
    • MFA phải phủ mọi nhánh login.
    • DevOps: IdP, rate-limit, log, secret kênh OTP.

    Câu hỏi ôn tập

    1. Vì sao message login khác nhau thành lỗ?
    2. Lockout theo username thất bại thế nào trước password spray?
    3. Reset password lấy Host từ request thì rủi ro gì?
    4. Remember-me cookie nên chứa gì, không chứa gì?
    5. API login có CAPTCHA UI nhưng không có throttle — hệ quả?

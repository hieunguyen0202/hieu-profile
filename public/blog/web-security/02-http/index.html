    Chương 2: HTTP Fundamentals

    Mọi lỗ hổng web đều đi qua một request. Đọc được request thì mới siết được Ingress.

    Tác giả: Hieu Nguyen (Ryan) Phần: I — Fundamentals Cập nhật: Aug 2026

    Khái niệm

    HTTP (HyperText Transfer Protocol) là ngôn ngữ trình duyệt và server nói với nhau. Ingress, Nginx, ALB, API gateway — tất cả chỉ là người chuyển bức thư đó.

    Với security, HTTP quan trọng vì:

    • Hầu hết tấn công web là HTTP (hoặc HTTPS) đã bị chỉnh header / query / body.
    • Lỗ hổng thường nằm ở cách app tin header, cookie, và parameter — không phải “protocol hỏng”.
    • Khi incident, access log và capture traffic chỉ có nghĩa nếu bạn đọc được cấu trúc.

    Cách hoạt động

    Mô hình request–response:

    Client (browser / curl / service)
        │
        │  HTTP request
        ▼
Gateway / Ingress / Nginx
        │
        ▼
App
        │
        │  HTTP response
        ▼
Client

    HTTP là stateless: request sau không “nhớ” request trước trừ khi bạn gắn trạng thái bằng cookie, session store, hoặc token. Đó là lý do session và JWT tồn tại — và là chỗ dễ cấu hình sai.

    Cấu trúc HTTP Request

    POST /api/login HTTP/1.1
Host: example.com
Content-Type: application/json
Authorization: Bearer eyJhbGc...
Cookie: session=abc123
User-Agent: Mozilla/5.0 ...
Content-Length: 45

{"username": "admin", "password": "secret"}
    • Request line: method + path + phiên bản — POST /api/login HTTP/1.1
    • Headers: metadata (Host, auth, cookie, content-type)
    • Dòng trống: tách header và body
    • Body: thường có với POST / PUT / PATCH; GET không nên mang side effect
    Trên Kubernetes, client không nói chuyện trực tiếp với Pod. Client nói với Ingress. Header Host, X-Forwarded-For, X-Forwarded-Proto thường bị gateway ghi đè — app phải tin đúng nguồn.

    Cấu trúc HTTP Response

    HTTP/1.1 200 OK
Content-Type: application/json
Set-Cookie: session=xyz789; HttpOnly; Secure; SameSite=Strict
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Content-Security-Policy: default-src 'self'
Content-Length: 89

{"status": "success", "token": "eyJhbGc..."}
    • Status line: phiên bản + mã + reason — HTTP/1.1 200 OK
    • Headers: gồm cả security headers (CSP, HSTS, cookie flags)
    • Body: JSON, HTML, file — tuỳ Content-Type

    HTTP Methods

    Method Mục đích Safe? Idempotent?
    GETĐọcCóCó
    POSTTạo / hành độngKhôngKhông
    PUTThay toàn bộ resourceKhôngCó
    PATCHSửa một phầnKhôngKhông
    DELETEXóaKhôngCó
    HEADNhư GET, không bodyCóCó
    OPTIONSHỏi method / CORSCóCó

    Ghi nhớ vận hành:

    • GET có side effect (xóa user qua query) → CSRF dễ hơn vì trình duyệt “đi” URL.
    • OPTIONS lộ CORS preflight — đừng mở Access-Control-Allow-Origin: * kèm credential.
    • PUT / DELETE trên Ingress phải đi kèm authz; không “mở method vì app cần lúc debug”.

    HTTP Status Codes

    2xx  thành công     200 OK · 201 Created · 204 No Content
3xx  chuyển hướng   301 Permanent · 302 Found · 304 Not Modified
4xx  lỗi client     400 · 401 · 403 · 404 · 429
5xx  lỗi server     500 · 502 · 503

    401 vs 403 — hay nhầm, và nhầm thì audit sai:

    • 401 Unauthorized: chưa chứng minh được danh tính (thiếu / sai token).
    • 403 Forbidden: đã biết bạn là ai, nhưng không đủ quyền.

    Trả 404 thay 403 để “giấu” resource là security through obscurity. Có thể giảm enumeration một chút; không thay access control.

    502 / 503 trên Ingress thường là Pod chết, probe fail, hoặc upstream timeout — đừng nhầm với “attacker đã vào”. Đọc access log + kube event trước khi nghĩ exploit.

    HTTP Headers quan trọng về Security

    Request headers

    Authorization

    Authorization: Bearer <jwt>
Authorization: Basic <base64(user:pass)>

    Rủi ro: token sống quá lâu, log nhét nguyên header, Basic auth trên HTTP. Gateway nên strip và không ghi Authorization ra access log.

    Cookie — session hijacking / CSRF nếu thiếu flag (mục cookie bên dưới).

    Host

    Host: example.com

    App hoặc template email nếu lấy Host từ request để ghép URL reset password → Host header injection. Ingress phải chỉ nhận server_name đã khai báo.

    X-Forwarded-For

    X-Forwarded-For: 1.2.3.4

    Chỉ tin khi request đến từ proxy bạn kiểm soát (Ingress, Cloudflare). App tự parse XFF từ internet → IP spoof, bypass rate-limit / geo allowlist.

    Content-Type — parser phải khớp body. Expect JSON mà nuốt XML thì mở cửa XXE (Part IV).

    Response — security headers

    Content-Security-Policy (CSP) — hạn chế nguồn script / frame; lớp chống XSS mạnh nhất phía browser.

    Content-Security-Policy: default-src 'self'; script-src 'self' https://cdn.example.com; object-src 'none'

    X-Frame-Options — DENY hoặc SAMEORIGIN: giảm clickjacking. CSP frame-ancestors là bản hiện đại hơn.

    Strict-Transport-Security (HSTS) — bắt browser chỉ HTTPS sau lần đầu; chống SSL stripping.

    Strict-Transport-Security: max-age=31536000; includeSubDomains; preload

    X-Content-Type-Options: nosniff — không cho browser đoán MIME.

    Referrer-Policy — ví dụ strict-origin-when-cross-origin: bớt leak token trong query khi nhảy site khác.

    Permissions-Policy — tắt camera / mic / geolocation nếu app không cần.

    Cookies — chi tiết

    Set-Cookie: session=abc123;
            Path=/;
            Domain=example.com;
            Max-Age=3600;
            HttpOnly;
            Secure;
            SameSite=Strict
    Attribute Ý nghĩa Nếu thiếu
    HttpOnly JavaScript không đọc cookie XSS đọc được session
    Secure Chỉ gửi trên HTTPS Dễ lộ trên HTTP / mixed content
    SameSite=Strict Không gửi khi request cross-site CSRF dễ hơn
    SameSite=Lax Gửi khi navigate top-level, không khi fetch cross-site Cân UX / CSRF
    SameSite=None Luôn gửi — bắt buộc kèm Secure Cần cho một số iframe / SSO; CSRF dễ hơn
    Domain / Path Phạm vi cookie Quá rộng thì subdomain chia session
    Expires / Max-Age TTL Session cookie: mất khi đóng browser (không phải “an toàn hơn” nếu máy dùng chung)

    HTTPS và TLS

    HTTPS = HTTP trên TLS. Handshake rút gọn:

    ClientHello  →  phiên bản, cipher
ServerHello  ←  cipher đã chọn
Certificate  ←  cert server
Key exchange
Finished     ↔  rồi mới tới HTTP đã mã hóa

    Vấn đề hay gặp trên cluster:

    • Cert hết hạn (cert-manager / ACME fail im lặng).
    • Self-signed trên môi trường “gần prod” → user click through, mất tín hiệu MITM.
    • TLS 1.0 / cipher yếu trên load balancer cũ.
    • Mixed content: trang HTTPS nhúng script HTTP.

    Kiểm tra cấu hình (lab / hệ thống của bạn):

    # testssl.sh trên host bạn được phép test
./testssl.sh https://example.com

# hoặc SSL Labs (public site): ssllabs.com/ssltest/

    HTTP/2 và HTTP/3

    • HTTP/2: binary, multiplexing nhiều stream trên một TCP, nén header (HPACK).
    • HTTP/3: QUIC trên UDP, mã hóa gắn với transport (TLS 1.3).

    Hệ quả bảo mật: request smuggling giữa HTTP/1.1 và HTTP/2 khác bản “cổ điển”; WAF / Ingress chưa parse HTTP/3 thì rule có thể không chạy trên path đó. Bật protocol mới trên LB thì phải biết layer inspect phía sau còn hiểu không.

    Cấu trúc URL

    https://user:pass@example.com:8443/api/v2/users?id=123&role=admin#section
 scheme   creds      host      port     path            query         fragment
    • User:pass trong URL vào access log, history, Referer.
    • Query thường bị log — token reset, PII không đặt trên query.
    • Fragment (#) không gửi lên server; JS trên trang đọc được.

    HTTP trong ngữ cảnh DevOps

    Nginx — security headers

    server {
    server_tokens off;

    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    add_header X-Frame-Options "DENY" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
    add_header Content-Security-Policy "default-src 'self'" always;
    add_header Permissions-Policy "camera=(), microphone=()" always;
}
    Trên Ingress-Nginx, dùng annotation / snippet tương đương. Header trùng giữa Ingress và app dễ bị ghi đè — chọn một nơi làm nguồn sự thật.

    Traefik (Kubernetes Middleware)

    apiVersion: traefik.io/v1alpha1
kind: Middleware
metadata:
  name: security-headers
spec:
  headers:
    stsSeconds: 31536000
    stsIncludeSubdomains: true
    frameDeny: true
    contentTypeNosniff: true
    referrerPolicy: strict-origin-when-cross-origin
    customResponseHeaders:
      Server: ""

    Log HTTP đúng cách

    log_format security '$remote_addr - $remote_user [$time_local] '
                    '"$request" $status $body_bytes_sent '
                    '"$http_referer" "$http_user_agent" '
                    '$request_time';

    Không log query có password / token. Mask Authorization và cookie session.

    Đọc một request như người vận hành

    GET /api/users/profile?userId=1337 HTTP/1.1
Host: api.example.com
Authorization: Bearer eyJhbGciOiJI...
Cookie: _ga=GA1.2.123; _session=xyz

    Khi review (staging, pentest được phép, hoặc code review):

    1. userId trên query — object ID do client chọn thường là dấu hiệu IDOR (access control, Part II).
    2. JWT trên Authorization — payload decode được; đừng nhét secret vào claim.
    3. Cookie session không có flag trên Set-Cookie tương ứng → sửa ở app hoặc gateway.
    4. State-changing API không có CSRF token / SameSite → ghi vào backlog.

    Kịch bản: Host Header Injection

    Server tin Host khi ghép link “quên mật khẩu”. Attacker gửi request (trên hệ thống được phép test) với Host không thuộc domain của bạn. Email chứa link trỏ sang host đó, token đi theo.

    Phòng:

    • Hardcode canonical URL trong config (BASE_URL, PUBLIC_HOST) — không lấy từ request.
    • Ingress chỉ server_name / host rule đã biết; default backend trả 404.
    • Không cache response theo Host chưa được allowlist (cache poisoning, Part VI).
    # Sai: tin Host từ client
reset = f"https://{request.headers['Host']}/reset?token={token}"

# Đúng: origin cố định
reset = f"https://{settings.PUBLIC_HOST}/reset?token={token}"

    Tóm tắt

    • HTTP: text (1.1) hoặc binary (2/3), request–response, stateless.
    • Siết method, status 401/403, và đừng log secret trên URL.
    • Security headers + cookie flags là lớp rẻ, làm ở Ingress được ngay.
    • Không tin Host / X-Forwarded-* trừ proxy tin cậy.
    • TLS 1.2+ (nên 1.3); theo dõi cert hết hạn.

    Câu hỏi ôn tập

    1. 401 khác 403 chỗ nào? Vì sao log SIEM cần phân biệt?
    2. Flag cookie nào chặn JavaScript đọc session? Thiếu thì gắn với lớp tấn công nào?
    3. HSTS làm gì, và tấn công nào nó nhằm giảm?
    4. Vì sao token không đặt trên query string?
    5. CSP chặn XSS theo cơ chế nào (một câu, đúng ý)?

    Chương 5: Session Management

    Session là chìa sau khi đã chứng minh danh tính. Làm mất chìa thì MFA cũng vô nghĩa.

    Tác giả: Hieu Nguyen (Ryan) Phần: II — Auth Cập nhật: Aug 2026

    Khái niệm

    Sau login, server nhớ bạn bằng session token (cookie hoặc header). Token phải khó đoán, gắn user, và chết đúng lúc.

    Yêu cầu bảo mật cho token

    • Entropy đủ (CSPRNG), không phải user-id encode.
    • Rotate lúc login (chống session fixation).
    • Invalidate lúc logout, đổi password, MFA xong.
    • Không nhét trong URL / Referer / log.

    Lớp sự cố thường gặp

    Session hijacking

    Token lộ: XSS đọc cookie thiếu HttpOnly, HTTP không Secure, log access, XSS stored. Phòng: flag cookie + CSP + HTTPS.

    Session fixation

    Attacker gài token trước login; nếu app không đổi token khi authenticate thì phiên đó thành của victim. Fix: luôn phát token mới sau login.

    Token yếu

    Tăng dần, timestamp, MD5(email). Scanner và log là đủ để nhận ra — không cần “bẻ”.

    Cookie attributes

    HttpOnly, Secure, SameSite, Domain/Path hẹp, Max-Age hợp lý — xem Chương 2. Session cookie Domain=.company.com quá rộng thì mọi subdomain chia phiên.

    Timeout

    • Idle timeout: không hoạt động thì chết.
    • Absolute timeout: dù đang dùng cũng phải re-auth (admin).
    • Logout server-side: xóa store, không chỉ xóa cookie client.

    JWT vs session server-side

    Session store (Redis) revoke được ngay. JWT stateless khó revoke trừ denylist/short TTL. Hybrid: access ngắn + refresh rotate.

    Cách phát hiện

    • Set-Cookie lúc login có đủ flag không.
    • Login có Set-Cookie mới hay giữ cookie cũ.
    • Logout còn dùng lại token được không (lab của bạn).

    Góc nhìn DevOps

    Sticky session vs Redis shared. TLS terminate ở Ingress thì cookie Secure vẫn set được nếu app tin X-Forwarded-Proto từ proxy tin cậy. Session store không public Service.

    Tóm tắt

    • Rotate session khi login.
    • Revoke lúc logout/đổi mật khẩu.
    • Cookie flags là lớp rẻ.
    • JWT ngắn hạn hoặc có cửa revoke.

    Câu hỏi ôn tập

    1. Fixation khác hijacking chỗ nào?
    2. Vì sao Domain cookie quá rộng nguy hiểm?

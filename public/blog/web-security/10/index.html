    Chương 10: CSRF

    Trình duyệt tự gửi cookie. Site khác có thể “ký tên bạn” nếu bạn không có token chống giả.

    Tác giả: Hieu Nguyen (Ryan) Phần: III — Client-side Cập nhật: Aug 2026

    Khái niệm

    CSRF: user đã login, cookie session tự đi theo request do trang khác khởi tạo. Server thấy phiên hợp lệ, thực hiện hành động user không cố ý.

    Điều kiện

    • Hành động quan trọng dựa cookie (không thêm secret request).
    • Không token/SameSite đủ chặt.
    • User đang có phiên.

    GET có side effect (unsubscribe, transfer) đặc biệt dễ. JSON thuần từ form cross-site khó hơn — đừng coi là đủ.

    Phòng chống

    1. Synchronizer CSRF token (per-session hoặc per-form), kiểm tra server.
    2. SameSite=Lax tối thiểu; Strict cho cookie nhạy.
    3. API: custom header (framework set) + SameSite; không tin Origin/Referer một mình.
    4. Re-auth cho hành động tiền / đổi email.

    Góc nhìn DevOps

    Cookie session thiếu SameSite trên Ingress. WAF rule CSRF không thay token app. Tách site thao tác (app) và site marketing origin.

    Tóm tắt

    • Cookie tự gửi là gốc CSRF.
    • Token + SameSite.
    • Không side effect trên GET.
    • Hành động nhạy cần re-auth.

    Câu hỏi ôn tập

    1. CSRF khác XSS chỗ nào?
    2. SameSite=Lax còn khe nào?
    3. Vì sao GET transfer nguy hiểm?
    4. Custom header giúp API thế nào?
    5. Logout CSRF có đáng lo?

    Chương 3: Burp Suite — đọc request cho đúng

    Không cần thành pentester. Cần thấy app thực sự gửi gì qua Ingress.

    Tác giả: Hieu Nguyen (Ryan) Phần: I — Fundamentals Cập nhật: Aug 2026
    Chỉ trỏ Burp vào lab của bạn, PortSwigger Academy, hoặc program có scope rõ. Production khách / công ty không nằm trong ủy quyền thì không phải “thực hành”.

    Khái niệm

    Burp Suite (PortSwigger) là intercepting proxy: ngồi giữa trình duyệt và server, ghi lại HTTP(S), cho phép xem và (trên hệ thống được phép) gửi lại request đã chỉnh.

    DevOps dùng nó để:

    • Xác nhận login / cookie / header thực tế — khác với “trên giấy kiến trúc”.
    • Nhìn API call SPA (browser không hiện trên thanh địa chỉ).
    • So response khi thiếu auth header, khi đổi host, khi cookie thiếu flag.

    Hai bản: Community (học, đủ Repeater / Proxy) và Professional (scanner, Collaborator — bản trả phí).

    Cài đặt

    Cần JDK hiện đại. Tải Community từ trang PortSwigger, rồi:

    java -jar burpsuite_community_*.jar

    GUI trong Docker thường khổ — học trên máy local. Kali có package sẵn nếu bạn đã dùng distro đó.

    Cấu hình ban đầu

    1. Proxy listener

    Mặc định 127.0.0.1:8080 (Proxy → Options / Settings → Proxy listeners).

    2. Trình duyệt

    Firefox: Settings → Network → Manual proxy → HTTP/HTTPS 127.0.0.1:8080. Extension kiểu FoxyProxy để bật/tắt nhanh, khỏi kẹt mọi tab qua Burp.

    3. CA certificate (HTTPS)

    TLS mã hóa end-to-end. Burp muốn đọc HTTPS thì browser phải tin CA của Burp. Khi proxy bật, mở http://burpsuite (hoặc help trong app) → tải CA → Import vào Firefox (Privacy → Certificates) và tin “identify websites”.

    Không cài CA: HTTPS fail hoặc bạn chỉ thấy CONNECT tunnel, không thấy path/header.

    Các module chính

    Proxy

    Intercept on: request dừng lại — Forward / Drop / sửa rồi Forward. Tắt intercept khi chỉ muốn ghi: dùng HTTP History.

    History là chỗ DevOps sống: filter host, status, MIME; chuột phải gửi Repeater.

    Repeater

    Gửi lại một request, đổi từng field, xem status / body / header. Dùng để kiểm tra giả định: bỏ Authorization, đổi Host sang giá trị không nằm allowlist, xem cookie có HttpOnly trên Set-Cookie không.

    Phím hay dùng (tùy keymap): gửi request, undo, chuyển tab Repeater.

    Intruder

    Lặp nhiều payload trên vị trí đánh dấu. Trên lab được phép: fuzz parameter, kiểm tra rate-limit login, liệt kê ID trong scope.

    Các attack type (khái niệm, không phải playbook):

    TypeÝ tưởng
    SniperMột vị trí, lần lượt từng payload
    Battering ramMọi vị trí cùng một giá trị
    PitchforkNhiều vị trí, hàng payload khớp nhau
    Cluster bombTổ hợp — tốn request, dễ đập lab

    Community giới hạn tốc độ Intruder. Không dùng để đoán mật khẩu hệ thống thật.

    Scanner (Pro)

    Active scan tự bắn payload. Chỉ trên target ủy quyền — có thể làm đầy log, làm hỏng dữ liệu test. DevOps thường thay bằng DAST trong CI (ZAP baseline) thay vì scan tay production.

    Decoder

    Base64, URL, HTML, hex, hash. JWT: phần header/payload là Base64URL — decode để đọc claim, không phải “bẻ” chữ ký.

    Comparer

    So hai response (độ dài, diff). Hữu ích khi hai lần gọi chỉ khác một header.

    Logger

    Traffic từ mọi module, rộng hơn HTTP History của Proxy — debug khi Repeater “biến mất” khỏi History.

    Collaborator (Pro)

    Kênh out-of-band: payload trên lab khiến app gọi DNS/HTTP ra server Collaborator. Dùng trong bài học SSRF / XXE mù — không nhắm hạ tầng người khác.

    Extensions (BApp Store)

    ExtensionKhi nào mở
    Param MinerTìm tên parameter / header ẩn (cache, app)
    JWT EditorXem / sửa JWT trên lab
    Logger++Log lọc tốt hơn
    AutorizeSo request với session user khác — access control

    Workflow: xem một API

    1. Bật proxy + CA; scope chỉ host lab.
    2. Dùng app như user: login, mở trang, gọi API.
    3. HTTP History: lọc path /api, method POST, status 401/403.
    4. Repeater: kiểm tra thiếu token, cookie flag, Host lạ.
    5. Ghi finding dạng misconfig (header, TLS, log) — đưa ticket platform, không “giữ PoC im”.

    Burp với Docker / Kubernetes

    Expose app lab ra localhost (-p 8000:8000) rồi proxy vào 127.0.0.1:8000. Cluster remote: kubectl port-forward Service — đừng mở NodePort ra internet “cho tiện test”.

    HTTPS trong container: cài CA vào trust store của image lab, hoặc chỉ test HTTP nội bộ.

    Burp giúp nhận ra misconfig nào

    • Response HTML chứa stack trace / version → giảm info leak.
    • Set-Cookie thiếu HttpOnly / Secure / SameSite.
    • Thiếu CSP, HSTS, nosniff trên response từ Ingress.
    • API state-changing bằng GET.
    • Cùng resource, user A vs user B khác body — tín hiệu access control (xem Part II).

    Góc nhìn DevOps

    Burp là tool tay. Pipeline cần DAST không GUI:

    docker run --rm -t ghcr.io/zaproxy/zaproxy:stable zap-baseline.py \
  -t https://staging.example.com \
  -r zap-report.html

    Staging phải isolat, credential test, rate-limit nhẹ để scan không thành DoS. Kết quả ZAP ≠ “sạch production”.

    Export History (lab) có thể đưa vào SIEM để luyện detection — không export session cookie production.

    Tóm tắt

    • Proxy + History: thấy traffic thật. Repeater: kiểm tra giả định từng request.
    • HTTPS cần CA Burp trong browser.
    • Intruder / Scanner chỉ trên scope; CI dùng ZAP/SAST/SCA.
    • Autorize / JWT Editor hỗ trợ đọc authz — không thay pentest ủy quyền.

    Câu hỏi ôn tập

    1. Vì sao HTTPS không hiện path trên History nếu chưa tin CA Burp?
    2. Intercept khác HTTP History chỗ nào?
    3. Sniper khác Cluster bomb ở chỗ nào? Cái nào dễ làm đầy quota lab?
    4. Autorize nhằm lớp lỗ hổng nào (một từ khóa OWASP)?
    5. App trong Docker: cách an toàn để Burp trên máy host thấy được traffic?

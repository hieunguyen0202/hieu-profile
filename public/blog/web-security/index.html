    Web Security cho DevOps Engineer

    Từ hạ tầng đến bảo mật ứng dụng web

    Tác giả: Hieu Nguyen (Ryan) Phiên bản: 1.0 Cập nhật: Aug 2026

    Bạn đang vận hành Kubernetes, viết pipeline CI/CD, chỉnh Nginx / Ingress, xoay secrets trên Vault — nhưng đã bao giờ dừng lại hỏi: ứng dụng chạy trên hạ tầng đó có thực sự an toàn không?

    DevOps và Security không phải hai ticket riêng. Ingress sai là attack surface. Secret nhét trong environment variable của Pod là cánh cửa. Pipeline không quét dependency là khoảng trống cho supply-chain. Series này ghi lại những gì một DevOps / platform engineer cần biết về bảo mật web — không để thành pentester trong 30 ngày, mà để nhìn ra lỗ hổng trước khi nó thành incident.

    Nguồn tham khảo chính

    • PortSwigger Web Security Academy
    • OWASP
    • RFC 7230, RFC 7231, RFC 6265, RFC 6749
    • CWE / CVE database
    • Tài liệu chính thức AWS, GCP, Azure, Kubernetes

    Lời mở đầu

    Hầu hết DevOps giỏi Linux, Docker, networking, và GitOps. Phần còn thiếu thường là cách ứng dụng web bị tấn công — XSS không phải “chuyện frontend”, SSRF không phải “chuyện backend”. Cả hai đều đi qua Ingress, Service, DNS nội bộ, và metadata API của cloud.

    Mục tiêu: hiểu hacker tư duy thế nào → nhận ra lỗ hổng trên đường đi của request → nhét kiểm soát vào workflow hàng ngày (review Helm, pipeline gate, secret rotation, log).

    Mỗi chương (khi viết) đi theo một công thức cố định:

    1. Nó là gì — khái niệm, không lý thuyết thừa.
    2. Tại sao xảy ra — assumption sai trong code hoặc hạ tầng.
    3. Hacker khai thác thế nào — mô hình tấn công, không phải playbook exploit.
    4. Cách phòng chống — control ở app và ở platform.
    5. DevOps cần làm gì — Ingress, NetworkPolicy, scanner, alert, runbook.

    Đọc tuần tự nếu mới bắt đầu. Đã quen cluster thì nhảy Part VIII (DevOps Security) song song với các chương auth / injection.

    Chương 12: SQL Injection

    String SQL cộng với input user. Database làm đúng những gì bạn vô tình viết.

    Tác giả: Hieu Nguyen (Ryan) Phần: IV — Injection Cập nhật: Aug 2026

    Khái niệm

    SQL injection: input trở thành câu lệnh. Lớp: error-based, UNION, boolean/time blind, second-order (lưu rồi query sau). Chi tiết kỹ thuật khai thác để học trên lab được phép (PortSwigger), không đem ra hệ thống thật.

    Phòng chống

    1. Parameterized queries / bind variables — control chính.
    2. ORM đúng cách (không raw concat).
    3. DB user least privilege: app không cần FILE / DBA.
    4. Input allowlist khi dynamic identifier (ORDER BY cột) — không nhét raw vào identifier.
    5. WAF: lớp phụ.

    Cách phát hiện

    SAST, code review concat SQL, error DB lộ trên staging, DAST trên lab. Production: không hiện SQL error cho client.

    Góc nhìn DevOps

    Secret DB không admin. NetworkPolicy: chỉ app subnet tới 5432. Log slow query, không log full bound params nếu có PII. Image không ship CLI dump lung tung.

    Tóm tắt

    • Bind parameters.
    • Ít quyền DB.
    • Ẩn lỗi SQL.
    • WAF không thay code.

    Câu hỏi ôn tập

    1. Vì sao escape tay kém prepared statement?
    2. Second-order là gì?
    3. App role DB nên thiếu quyền nào?
    4. ORM vẫn SQLi khi nào?
    5. Hiện stack SQL trên 500 page hại gì?

    Chương 8: JWT

    JWT tiện vì stateless. Tiện đó cũng là chỗ revoke và thuật toán bị làm ẩu.

    Tác giả: Hieu Nguyen (Ryan) Phần: II — Auth Cập nhật: Aug 2026

    Khái niệm

    JWT: header.payload.signature (Base64URL). Payload đọc được — không mã hóa. Chữ ký mới là control.

    Cấu trúc

    Header: alg, typ, kid. Payload: sub, exp, iss, aud, role… Signature: HMAC hoặc RSA/ECDSA. Decode trên lab để đọc claim; đổi claim mà không ký lại thì gateway phải reject.

    Lớp bug thư viện / config

    • Tin alg từ token (none / nhầm RS↔HS).
    • Secret HMAC yếu hoặc default.
    • Nhận JWK/jku/kid từ attacker (SSRF + key confuse).
    • TTL dài, không exp, không check aud.
    Phòng: pin algorithm trên server, lấy key từ JWKS nội bộ allowlist, không từ header token.

    Phòng chống

    • Verify chữ ký với key cố định / JWKS tin cậy.
    • TTL ngắn; refresh rotate.
    • Không nhét PII/secret vào payload.
    • Denylist jti khi logout nếu cần cắt ngay.

    Góc nhìn DevOps

    API gateway (Kong, Istio JWT, Cloud Armor) verify iss/aud/exp. JWKS cache + rotation. Log sub không log raw token.

    Tóm tắt

    • Payload không bí mật.
    • Pin alg + key.
    • exp/aud/iss bắt buộc.
    • Gateway verify một nơi.

    Câu hỏi ôn tập

    1. JWT khác session cookie chỗ revoke?
    2. Vì sao không tin alg trên token?
    3. kid nguy hiểm khi nào?
    4. Claim nào gateway nên bắt?
    5. Access token sống 24h thì trade-off gì?

    Chương 20: Race Condition

    Hai request cùng lúc. Số dư, coupon, unique constraint — ai commit trước.

    Tác giả: Hieu Nguyen (Ryan) Phần: V — Server-side Cập nhật: Aug 2026

    Khái niệm

    Time-of-check vs time-of-use: kiểm tra còn 1 coupon rồi hai request đều redeem. Cần atomicity trên DB, không “if” trên app đơn luồng.

    Phòng chống

    • Transaction + constraint unique.
    • Idempotency-Key trên API thanh toán.
    • Lock pessimistic/optimistic version.
    • Hàng đợi một consumer cho nghiệp vụ tiền.

    Góc nhìn DevOps

    N replica không tạo race — DB mới là chỗ arbitrate. Rate-limit không thay unique constraint. Test load lab trên endpoint tiền.

    Tóm tắt

    • Atomic DB.
    • Idempotency key.
    • Đừng tin check-then-act.
    • Scale-out làm race dễ lộ hơn.

    Câu hỏi ôn tập

    1. TOCTOU nghĩa là gì?
    2. Unique constraint cứu coupon thế nào?
    3. Idempotency-Key dùng khi nào?
    4. Vì sao 1 replica app vẫn race?
    5. Queue giúp gì?

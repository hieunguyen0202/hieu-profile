    Chương 7: OAuth 2.0

    OAuth ủy quyền — không phải “login Google là xong bảo mật”.

    Tác giả: Hieu Nguyen (Ryan) Phần: II — Auth Cập nhật: Aug 2026

    Khái niệm

    OAuth 2.0: resource owner cho client truy cập resource server với scope giới hạn. OpenID Connect thêm identity. DevOps hay đứng ở IdP, redirect URI, và secret client.

    Flows

    • Authorization code (+ PKCE): mặc định cho web và SPA/mobile.
    • Implicit: token trên fragment — deprecated, đừng bật.
    • Client credentials: service-to-service, không user.

    Lỗ thường gặp

    • Thiếu state (CSRF trên consent).
    • redirect_uri khớp tiền tố lỏng → token/code về host lạ.
    • Token trên query → Referer/log.
    • Không kiểm tra aud/iss/expiry.
    • Scope rộng hơn user đồng ý.
    • Liên kết account theo email chưa verify.

    Phòng chống

    • Redirect URI allowlist exact match.
    • PKCE bắt buộc public client.
    • state/nonce ngẫu nhiên, one-time.
    • Secret client chỉ trên backend; SPA dùng public + PKCE.
    • Map IdP user theo subject ổn định, không chỉ email.

    Góc nhìn DevOps

    Cấu hình IdP (Keycloak/Entra/Cognito) là production config: đừng wildcard redirect. Secret client trong Vault. Callback URL chỉ HTTPS. Log token exchange lỗi, không log code/token.

    Tóm tắt

    • Code flow + PKCE.
    • redirect_uri chặt.
    • state chống CSRF consent.
    • Đừng implicit.

    Câu hỏi ôn tập

    1. state làm gì?
    2. Vì sao prefix match redirect_uri nguy hiểm?
    3. PKCE giải quyết vấn đề gì của public client?
    4. Token trên query lộ đường nào?
    5. Liên kết account theo email chưa verify rủi ro gì?

    Chương 11: XSS

    Browser tin HTML/JS bạn nhét vào trang. Output encoding và CSP là hai lớp phải có.

    Tác giả: Hieu Nguyen (Ryan) Phần: III — Client-side Cập nhật: Aug 2026

    Khái niệm

    XSS: dữ liệu không tin được chạy như script trong phiên user. Hậu quả: đọc DOM, hành động với cookie không HttpOnly, deface — không cần “payload showcase” để hiểu risk.

    Ba loại

    • Reflected: input về ngay response.
    • Stored: lưu DB/comment rồi mọi victim mở.
    • DOM-based: JS client lấy location/hash nhét innerHTML.

    Phòng chống

    1. Output encoding đúng context (HTML, attr, JS, URL).
    2. Tránh innerHTML / eval với dữ liệu user.
    3. CSP: default-src 'self'; không unsafe-inline nếu được nonce/hash.
    4. Cookie session HttpOnly.
    5. Framework auto-escape (React default) — vẫn cẩn dangerouslySetInnerHTML.

    Cách phát hiện

    Lab PortSwigger / pipeline DAST. Code review sink HTML. CSP report-uri trên staging.

    Góc nhìn DevOps

    CSP header tại Ingress. Không serve user-upload với text/html trên origin app. WAF XSS signature là lớp phụ, dễ bypass — không phải control chính.

    Tóm tắt

    • Encode output.
    • CSP siết script.
    • HttpOnly session.
    • Stored XSS rộng hơn reflected.

    Câu hỏi ôn tập

    1. Stored khác reflected?
    2. DOM XSS nằm tầng nào?
    3. CSP unsafe-inline làm yếu gì?
    4. HttpOnly chặn XSS đọc cookie chứ không chặn gì?
    5. Upload HTML trên cùng origin rủi ro gì?
